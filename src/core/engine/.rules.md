# engine/ 模块编码规范

> 本文档补充 CODE_WIKI.md 的架构说明，聚焦 AI 协作者在 engine/ 模块中的常见错误和硬约束。

## 数据流约束

- `pipeline-guard.js` 的 guard 函数必须返回 `{ allowed: boolean, reason?: string }` 形状
- `update.js` 是写入的唯一入口，其他模块不得直接操作 IndexedDB
- pipeline 的触发入口在 `pipeline-guard.js`，不是 `update.js`

## AI 常见错误

1. **不要在 pipeline 中间步骤直接调用 `store.save()`**
   - pipeline 的写入必须通过 `update.js` 的 pipeline 入口
   - 只有 `garbage-collector.js`、`tools.js` 等非 pipeline 路径可以直接操作 store

2. **修改 prompt 模板时，必须同步检查 `injection.js` 中的格式匹配**
   - prompt 的输出格式与 injection 的解析格式必须一致
   - 修改 `template-llm.js` 中的模板后，跑 `smartpush-12-prompt-structure` 测试用例验证

3. **`retrieval.js` 修改检索逻辑时，必须跑 `test-cases/retrieval/` 下的集成测试**

4. **`consolidate.js` 的 LTM 合并逻辑不可跳过**
   - 新增 arc 时必须在 `ltm_arcs_by_id` 和 `ltm_arcs` 两个位置同步写入

5. **修改 `bm25-grouper.js` 的分组逻辑后，必须跑 `smartpush-group-a` / `smartpush-group-b` 测试**
