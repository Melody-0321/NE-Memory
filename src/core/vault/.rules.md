# vault/ 模块编码规范

> 本文档补充 CODE_WIKI.md 的架构说明，聚焦 AI 协作者在 vault/ 模块中的常见错误和硬约束。

## Schema 变更约束

- `schema.js` 中的任何字段增删都必须同步更新 `CODE_WIKI.md` §2 Vault Schema
- `state-versions.js` 的 delta 兼容逻辑需覆盖新旧字段的迁移路径
- 新增 Vault 字段类型属于 AGENTS.md 中的「第二层提醒」级变更

## AI 常见错误

1. **`store.js` 的 CRUD 操作必须通过 `this.db`（IndexedDB），不是内存对象**
   - `store.js` 封装了 IndexedDB 的事务管理，不要在外部绕过它直接操作数据库

2. **修改 Schema 字段类型后，必须处理旧数据兼容**
   - 新增字段 → 给默认值
   - 删除字段 → 保留读取能力（读旧数据不报错）
   - 修改类型 → 写 migrate 函数

3. **`state-versions.js` 新增 delta 类型时，必须同步更新 `garbage-collector.js` 的清理逻辑**
   - 每种快照类型在 gc 中有对应的清理策略

4. **`retrieval-filter.js` 的过滤逻辑修改后，必须跑 `test-cases/pipeline/state-field-validate` 验证**
