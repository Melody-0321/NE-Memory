# Message Identity System

- 状态：已接受（v7.0 落地，P0 强化）
- 日期：2026-08-16

## 背景（Context）

消息去重、回滚、跨消息引用都需要稳定的消息身份，而早期依赖消息在 chat 数组中的**下标**。问题：

- **下标脆弱**：消息被删除/重排/合并后下标漂移，基于下标的查找与引用全部失效。
- **去重不可靠**：无法稳定判断"这条消息是否已处理"，增量更新可能重复提取或漏记。
- **跨消息引用崩溃**：`[→msgId]` 引用因未声明变量抛 `ReferenceError`，`msg#N`/裸数字引用在消息存在时也 100% 失败（改名时漏改用法）。

## 决策（Decision）

建立消息身份系统（`src/core/engine/msg-id.js`）：

- **`__ne_msg_id` 注入**：每条消息在入库时注入稳定 ID，格式 `"{idx}_{send_date}_{role}"`（如 `3_2026-07-09T06:55:00.000Z_user`）。
- **`buildMsgId`**：从 ST 消息对象生成稳定 ID；idx 前缀支持 O(1) 反问，不传时降级为 `?` 标记。
- **`findMessageInChat` O(1) 反问 + 漂移兜底**：解析 idx 前缀 → `chatMessages[idx]` O(1) 反问 → send_date 校验命中即返回 → 不匹配则 O(n) 漂移兜底（删除/重排后）→ 最终按 send_date+role 全量遍历；支持裸数字（`"95"`/`"msg#95"`）走数组下标 O(1) + id 身份校验。
- **统一消息索引**：idx 前缀能力接入统一索引，守卫修复 `!msgId` 误拦合法下标 0 的边界。

## 后果（Consequences）

**正面**

- 去重/回滚/引用全部基于稳定身份，O(1) 查找显著提速。
- 增量更新不再重复处理（msg_id 去重 + cursor 游标追踪），事件记忆消耗不随对话长度增长。
- 跨消息引用（`access` 工具）稳定可用。

**负面**

- 消息索引需维护：存量消息需补标 `__ne_msg_id`，删除/重排时索引需同步。
- 依赖 send_date 作为稳定分量，异常 send_date 需降级路径兜底。
- 漂移兜底 O(n) 全量扫描在极端长对话下仍是最后防线，需与 O(1) 主路径配合。
